# 第一批合成足球事件

本目录完全使用虚构球队、球员与人工设计的比赛情景，没有复制真实比赛记录。
字段组织参考 [StatsBomb Open Data](https://github.com/hudl/open-data)。
这是精简的 **StatsBomb-inspired 自定义格式**，不是官方格式的完整实现，
不承诺可直接交给官方格式的解析器使用。

## 文件

- `match.json`：虚构比赛、参与球员、坐标与时间约定。
- `events.json`：传球、接球、带球、射门及扑救事件。
- `clips.json`：三个关键片段的事件引用、比分变化和视频生成约束。

三个片段分别在第 12、34、67 分钟发生，结果为进球、射偏、扑救。
它们是离散的技术验证片段，**不是完整比赛流**；不能据此计算全场控球率、
全场传球成功率或其他需要完整事件覆盖的统计。

## 使用

在仓库根目录运行：

```powershell
python scripts/generate_synthetic.py
```

只使用 Python 标准库。生成结果固定且可复现，执行时检查事件引用、
时间顺序、关键动作衔接、结果与比分一致性。

视频流程应从 `clips.json` 选取片段，再通过事件 ID 查询完整事件链。
`shot.freeze_frame` 仅表示射门瞬间的局部位置快照，不代表全部 22 人，
也不是图像、连续追踪数据或真实的眼睛朝向。

## 约定与简化

- x/y 为 120 × 80 的球场归一化坐标，不能直接当成米。
- 所有片段都归一化为进攻朝 x 增大方向；门线 x=120，门口 y=36..44。
- 射门终点第三维 z 单位为米。
- `minute` 是全场累计分钟；`timestamp` 是当前半场内的时间。
- `Pass` 的 `outcome: Complete` 是本项目的显式约定。
- 事件类型等枚举仅保留名称，省略官方枚举 ID。
- 不提供 StatsBomb xG，也不虚构真实模型输出。
- 球员位置与结果是人工设计；动作补间、头部朝向、音效属于生成表现。
- `generation_constraints` 是项目自定义字段，不属于 StatsBomb 标准。
- 当前生成器提供固定样例，不代表已完成概率模拟、完整规则或真实感验证。

生成内容应标注“合成比赛 / AI 场景演绎”。后续可在此基础上增加不同位置、
进攻路线及防守布局的受约束采样，并单独验证运动速度、越位与碰撞等逻辑。
